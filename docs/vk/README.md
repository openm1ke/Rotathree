# Rotathree: черновик VK, приложение 54815388

Это локально подготовленный кандидат для тестового запуска, не опубликованная игра и не подтверждение прохождения модерации. Доступ к консоли dev.vk.com/dev.vk.ru заблокирован проверкой безопасности браузера. Поля приложения не заполнены, действующие правила из кабинета не прочитаны. App ID взят из адреса открытой пользователем страницы.

## Сборка и разделение версий

Ветка `codex/vk-games` содержит платформенный адаптер поверх общей React/TypeScript игры. Обычная версия собирается `npm run build` в `webapp/dist`; VK — `npm run build:vk` в `webapp/dist-vk`. Pages workflow собирает обычный сайт из `main`, VK — из `codex/vk-games`, затем публикует их вместе: обычную игру в корне, VK в `/vk/`. Workflow должен быть одинаковым в обеих ветках; обе ветки разрешены для окружения `github-pages`. Обновление любой версии сохраняет вторую. `vk-release.yml` дополнительно собирает ZIP-артефакт; отправки на модерацию VK нет.

Адрес VK-сборки: `https://openm1ke.github.io/Rotathree/vk/`. Один адрес указывается во всех трёх полях размещения VK: «Мобильное приложение», «Web», «Мобильная версия сайта». Интерфейс адаптивный. Эта сборка ожидает запуск внутри VK; открытие адреса напрямую в обычном браузере не заменяет проверку через платформу.

```sh
cd webapp
npm ci
npm run check
npm run test:e2e
npm run build:vk
cd ..
python3 tool/package_vk.py
```

Результат: `build/releases/vk/Rotathree-vk-draft.zip`. В корне ZIP — `index.html`. Проверяется комплектность, число музыкальных треков и целостность ZIP; рядом создаётся SHA-256. ZIP можно распаковать на отдельном HTTPS-хостинге либо загрузить через предусмотренный платформой механизм, если он доступен в данном типе приложения. Наличие загрузки ZIP в этом кабинете пока не подтверждено. Не использовать обычную Pages-сборку как адрес VK-игры: она не включает адаптер платформы. Если используется iframe-хостинг, он должен разрешать встраивание со стороны VK; запрет `X-Frame-Options: DENY/SAMEORIGIN` не подходит. Точные разрешённые источники CSP следует взять из актуальной документации VK, не подставлять wildcard наугад.

Общие исправления игры переносить между main и этой веткой через небольшие PR/merge, платформенные различия держать в `src/platform` и build mode. Не копировать игровой движок во вторую самостоятельную кодовую базу.

## Что добавлено

- Официальный `@vkontakte/vk-bridge` 3.0.2; `VKWebAppInit` и параметры запуска, проверка App ID. Авторизация через OAuth, профиль, друзья, телефон, почта, уведомления, реклама и платежи не запрашиваются.
- Настройки, кампания, кастом, статистика, обучение и слоты партий читаются из VK Storage **до** запуска React. Локальная копия раздельна по App ID и User ID. Входные параметры не используются как серверное доказательство личности; сервера авторизации у игры нет.
- Большие сохранения разбиваются на ASCII-части по 1800 символов, до 32 частей в банке. Используются два банка; манифест переключается после подтверждения всех записей. Это выбранные консервативные параметры реализации, а не подтверждённые актуальные квоты VK. Чтения группируются не более чем по 10 ключей.
- Игровые изменения пакетируются раз в 5 секунд, скрытие/закрытие вызывает немедленный flush. Локальная копия пишется синхронно. Завершение сетевого запроса после закрытия браузера не гарантировано. Неподтверждённая копия восстанавливается при следующем запуске, если облако не изменилось; при конфликте устройств предлагается явно выбрать сохранение.
- При сбое загрузки облака игра не запускается с пустыми сохранениями: можно повторить или выбрать локальный режим. Локальный режим показывает постоянное уведомление; ошибки синхронизации показывают кнопку повтора.
- VK ViewHide/ViewRestore останавливают игровое время и музыку, отпускают удерживаемые кнопки. Музыка возвращается при восстановлении, если включена; браузер может потребовать жест для звука.
- Учитываются insets VK, мобильная платформа и язык VK. Ручной выбор языка имеет приоритет. Сенсорные крестовины и компактное обучение сохранены.
- Только пять треков с документированным CC0; Deep Focus не включены до подтверждения прав. В пакете `credits.html` и лицензии шрифта, SDK и React. Подтверждение лицензий музыкальных исходников — `assets/music/downloaded/SOURCES.md`.

## Карточка и документы

Тексты и значения для переноса в форму — `submission.json`. Null означает, что данных нет: имя разработчика, контакт поддержки, маркировка, HTTPS-адрес игры и документов. `privacy-policy.draft.md` и `terms.draft.md` — черновики, не включённые в игровой ZIP. Они описывают текущую реализацию; необходимо вписать данные владельца и хостинга, проверить требования платформы и утвердить окончательные тексты. Соглашения с VK принимаются владельцем приложения отдельно, не этим черновиком.

Иконки — утверждённый логотип на тёмно-синем фоне с бледной сеткой, 512 и 1024 px. Скриншоты — реальная игра на локальном стенде VK Bridge: desktop 1280×720, mobile 390×844. Это исходные варианты, размеры из кабинета пока не подтверждены; их можно адаптировать после получения требований. Скриншоты не доказывают запуск на реальной платформе.

## Проверка на реальной платформе перед модерацией

1. Убедиться, что создан нужный тип HTML5-игры для каталога VK Игры, а не другой тип приложения. Получить актуальные правила из кабинета.
2. Разместить отдельный dist-vk по HTTPS или загрузить ZIP, если кабинет предоставляет такую функцию. Указать адреса десктопной/мобильной версии по фактическим полям формы. Открыть приложение 54815388 внутри VK.
3. Проверить VKWebAppInit, GetLaunchParams/GetConfig, StorageGet/Set, реальные квоты, возврат после сворачивания, браузерные и native VK iOS/Android клиенты. Проверить новую игру, смену громкости, закрытие, продолжение кампании и кастома, другое устройство, отказ хранилища.
4. Проверить Firefox Windows, узкий портретный экран, все клавиши, Enter/Backspace в обучении, отсутствие перекрытий панелями VK. Пройти кампанию и доступ к «Кошмару».
5. Перенести тексты карточки и изображения, проверить ограничения размеров/символов и маркировку. Вписать владельца/поддержку, опубликовать окончательные документы и указать их URL. Проверить права на все ресурсы и требования по соглашениям.
6. Владелец приложения принимает актуальные соглашения и отправляет игру на модерацию после проверки кандидата. Обязательность конкретных соглашений/URL и полей должна быть подтверждена формой кабинета.

## Локальная проверка адаптера

```sh
cd webapp
npm run dev:vk -- --host 127.0.0.1 --port 5184
```

Открыть `http://127.0.0.1:5184/e2e/fixtures/vk-host.html`. Стенд имитирует публичные события SDK и хранилище для фиктивного пользователя 1; в ZIP не входит. Есть переключение мобильного экрана, сворачивание, возврат, отказ хранилища и перезапуск. Для проверки production: запустить `python3 -m http.server 5185 --bind 127.0.0.1 --directory webapp/dist-vk` из корня, открыть стенд с параметром `?game=http://127.0.0.1:5185/`. Это тест собственного приложения, не подключение к консоли VK.

Проверенные первичные источники: [официальный SDK](https://github.com/VKCOM/vk-bridge) и типы опубликованного npm-пакета 3.0.2; [официальный старый пример Direct Games](https://github.com/VKCOM/vk-direct-games-example) — только историческая справка, не источник текущих требований модерации.
