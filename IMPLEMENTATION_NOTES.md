# Изменения после аудита · обновлено 9 октября 2026

В проекте две самостоятельные реализации правил: Flutter/Dart и React/TypeScript.
Алгоритмы генерации остаются разными. Сохранение восстанавливает поток фигур внутри
той же платформы; одинакового результата между платформами не требуется.

Независимые слоты кампании, кастома и кошмара; старый одиночный слот переносится. Продолжение выбранной игры начинается на паузе. |
| Переход уровня под паузой | Таймер баннера и движок стоят под паузой и настройками; оставшееся время и следующий уровень входят в сохранение. В браузере останавливается также CSS-анимация баннера. |
| Потеря статистики при выходе | «Завершить партию», повтор и запуск новой партии того же режима записывают прерванный результат. Обычный выход автоматически сохраняет игру. Стабильный ID предотвращает повторную запись. |

| Нет обучения | Шесть шагов перед первой партией, практические упражнения, остановленное автоматическое падение, пропуск и повтор из меню. Выбранные кнопки, автоповтор, размеры и позиции применяются и в обучении. Подсказки показывают текущие назначения; для неназначенного действия есть учебная кнопка. Снимки проверяются перед применением: размеры, координаты, цвета, фазы, времена,
очередь ввода и наличие фигур/падающей фигуры/строящегося стакана для каждой стороны.
Повреждённый или несовместимый снимок отклоняется. Это локальные сохранения, без
облачной синхронизации. При принудительном завершении процесса до записи возможна
потеря изменений после последнего снимка. Удаление данных приложения/браузера
удаляет сохранения.

Обычные снимки создаются каждые две секунды игрового времени, после значимых событий,
на паузе, при открытии настроек и уходе в фон. Автоповтор движения не вызывает
полную запись на каждом повторе. Flutter выполняет записи последовательно.

## Публикация Android

Debug-сборка сохраняет прежний ID. Для release нужен реальный ключ владельца:

1. Скопировать `android/key.properties.example` в игнорируемый Git файл
   `android/key.properties` и заполнить путь к keystore и данные подписи.
2. Задать `ROTATHREE_APPLICATION_ID` либо Gradle property `rotathreeApplicationId`
   с ID публикации, отличным от `com.example.*`.
3. Выполнить `flutter build appbundle --release`.

Вместо файла ключа можно задать `ROTATHREE_KEYSTORE`, `ROTATHREE_STORE_PASSWORD`,
`ROTATHREE_KEY_ALIAS`, `ROTATHREE_KEY_PASSWORD`. Ключи и пароли не входят в репозиторий.
Для уже опубликованного приложения следует использовать его прежний ID и ключ.
В этой работе ключ публикации не предоставлялся: собран debug APK и проверен
отказ release без параметров подписи. Публикация Android-приложения не выполнялась. Веб-версия публикуется через GitHub Pages.
