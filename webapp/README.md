# Rotathree — веб-версия

Та же игра, что и во Flutter-проекте уровнем выше, для браузера: клавиатура на компьютере и две крестовины на телефоне.

Играть: https://openm1ke.github.io/Rotathree/ — страница собирается из этой
папки и публикуется через GitHub Actions (`.github/workflows/pages.yml`) при
каждом пуше в `main`, который её затрагивает.

Стек такой же, как у веб-порта RuneChess: **Vite + TypeScript + React**, тесты —
**Vitest**. Игровой движок в `src/game` — чистый TypeScript без React и DOM,
построчный порт `lib/game` из Flutter-проекта.

## Запуск

```bash
npm ci # Node 22.12+ (ветка 22), либо поддерживаемая Vitest ветка 24/26
```

```bash
npm run dev
```

Откроется на `http://localhost:5183`.

## Проверки

```bash
npm run check
```

Это `typecheck` + `lint` + `test` + `build` подряд.

## Режимы

Главное меню: **Кампания**, **Кастом**, **Статистика**, **Настройки**.

- **Кампания** — пятнадцать уровней. Каждый уровень — цель в очках, которую
  нужно набрать на текущих стаканах и цветах. Уровни идут этапами по числу
  цветов (3, 4, 5, 6); в каждом этапе стаканы добавляются по одному. Новый стакан
  вырастает из центра, и только потом в него падает первая фигура. Очки уровня
  считаются заново, а доска сохраняется; новый этап очищает поле. Цели подобраны
  по симуляции ботов (`tool/campaign_sim.dart` в корне проекта): исторические оценки отдельных уровней сделаны на пустом поле.
  Непрерывная кампания теперь проверяется отдельно через `tool/campaign_run_sim.dart`. Последние три
  уровня немного ускоряют падение.
- **Кошмар** — открывается после прохождения кампании: шесть цветов, четыре
  стакана. Скорость растёт на каждую тысячу очков, пока стакан не заполнится.
- **Кастом** — своя игра: от 0 до 3 дополнительных стаканов, от 3 до 9 цветов,
  длина рукава, стартовая скорость, ускорение (шаг и интервал очков) и правило
  после хлопка. Настройки режима запоминаются и не влияют на кампанию и кошмар.

Статистика по каждому режиму: партии, очки, фигуры, матчи, лучшее комбо, время,
лучший уровень или скорость, и последние партии.

## Управление

Клавиши по умолчанию (меняются в «Настройки → Управление», привязка идёт к
физической клавише, поэтому раскладка не важна):

| Действие | Клавиши |
|---|---|
| Сдвиг фигуры влево / вправо | A / D (с автоповтором) |
| Поворот по часовой | W |
| Поворот против часовой | не назначен |
| Мягкий сброс (держать) | не назначен |
| Сброс | S или пробел |
| Стакан слева / справа | ← / → |
| Стакан напротив | ↑ или ↓ |
| Пауза | Esc или P |
| Заново | N |

Крестовины появляются при мобильном user-agent (включая iPad с desktop user-agent)
или при ширине окна до 600 CSS px в вертикальном виде. На мобильном браузере они
остаются доступны и в альбомной ориентации. Удержание движения использует DAS/ARR,
два пальца можно использовать одновременно. Настройка крестовин открывается вместо
редактора клавиатуры; при расширении обычного окна возвращается клавиатурный интерфейс.

В меню стрелки и W/S двигают фокус, Enter открывает, Esc или Backspace — назад.

## Структура

```
src/
  game/        движок: config, board, glass, piece, placement, matchDetector,
               gravity, cascade, generator, incoming, engine; campaign, modes, session — уровни, режимы, сессии
  render/      canvas: renderer (поле, блоки), effects (толчки, частицы), theme,
               quality (разрешение по возможностям машины)
  input/       bindings (привязки клавиш), keyboard (автоповтор DAS/ARR), pads (мультитач), touch (адаптация)
  services/    storage (localStorage), runSave (валидация сохранённой сессии)
  components/  MainMenu, CampaignScreen, CustomScreen, StatisticsScreen,
               SettingsScreen, GameScreen, Hud, LevelBanner, ui (общие элементы)
  styles/      tokens.css, global.css
  tests/       model, engine, progression, campaign, input, effects, storage, theme
```

## Скорость отрисовки

Кадр рисуется целиком каждый раз, поэтому в нём нет ничего дорогого:

- клетка — целое число пикселей экрана, центр креста стоит на границе
  пикселя, так что блоки копируются на холст один в один, без пересчёта;
- свечения (активный стакан, ореол фигуры, предупреждение) нарисованы один
  раз в картинки: тени canvas (`shadowBlur`) во время игры не используются;
- линии сетки — готовые `Path2D`, градиенты создаются один раз;
- место приземления фигуры считается раз за шаг, а не несколько раз за кадр;
- под паузой и на итоговом экране неизменившаяся картинка не перерисовывается;
- фон — обычные градиенты без `filter: blur`;
- если машина всё равно не успевает (в среднем меньше ~45 кадров в секунду),
  поле рисуется в меньшем разрешении — см. `render/quality.ts`. Если это не
  помогло (браузер сам ограничивает частоту), разрешение возвращается.

В режиме разработки `window.__rotathree` — движок, `window.__rotathreeView` —
отрисовщик и эффекты: ими удобно мерить стоимость кадра.

## Настройки

Четыре вкладки; всё сохраняется сразу:

- **Управление** — клавиши (два слота на действие) либо крестовины; автоповтор движения.
- **Цвета** — девять цветов фигур. Стандартные наборы — «Классика», «Пастель»,
  «Неон»; изменяя цвет стандартного набора, вы получаете его копию. Свои наборы
  можно сохранять и удалять.
- **Эффекты** — взрывы: разная анимация для каждого типа совпадения или одна
  для всех; тряска поля; длительность поворота поля.
- **Интерфейс** — подсказки клавиш, очки и комбо, время и фигуры, непрозрачность
  надписей.

Хранятся в `localStorage`: настройки (`rotathree.settings.v2`), прогресс
кампании (`rotathree.progress.v1`), статистика (`rotathree.stats.v1`) и настройки
кастома (`rotathree.custom.v1`), партии (`rotathree.run.web.v1`) и прохождение
обучения (`rotathree.tutorial.v1`). Ошибка любой записи показывается во всём приложении
с кнопкой повторной попытки. При удалении данных браузера сохранения пропадут.

Перед первой игрой запускается обучение с шестью шагами; его можно пропустить
или повторить из меню. Падение в упражнениях остановлено, практика не идёт в статистику.

Партия сохраняется раз в две секунды игрового времени, после размещений, совпадений,
добавления стакана и ускорения, при паузе, скрытии/закрытии вкладки и открытии настроек.
Выход «В меню», «К уровням» и «Изменить режим» также сохраняет текущую партию.
Кампания, кастом и кошмар имеют независимые слоты. «Продолжить» открывает выбор
сохранённой игры и восстанавливает её на паузе. Старый одиночный слот переносится
автоматически. «Завершить партию» удаляет только выбранный слот и записывает
прерванный результат; новая игра заменяет сохранение только своего режима.
Диалоги удерживают фокус; пробел и Enter активируют выбранную кнопку.

В мобильных настройках доступны размер каждой крестовины и перетаскивание в
превью разрешённой области под полем. Размер — 136–216 CSS px с ограничением
по доступной ширине; крестовины не перекрываются и остаются внутри экрана.
Положение и размер сохраняются, адаптируются к изменению окна и используются
также в обучении. Подсказки обучения учитывают назначенные кнопки. Если нужное
действие снято со всех кнопок, упражнение можно выполнить отдельной учебной кнопкой.

Dart и TypeScript сохраняют свои генераторы: одинаковые сиды между платформами
не обязаны давать одинаковые фигуры. Сохранения имеют отдельные форматы и ключи.

## Проверки

```bash
npm run check
npm audit --audit-level=moderate
npm run test:e2e # локально Chrome; в CI Playwright Chromium
```

Экран кампании — единый список уровней с бейджами количества цветов, стаканов
и скорости в секундах на шаг. В кастоме квадратные кнопки и все целые длины
рукава от 4 до 12. Камера вписывает открытые стаканы в область поля; при добавлении
сначала отдаляется, затем вырастает новый рукав. Счёт и статистика вынесены над
полем. `prefers-reduced-motion` отключает движение камеры и рост рукава.
